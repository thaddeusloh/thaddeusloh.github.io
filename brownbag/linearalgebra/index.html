MA1522 · 01 · Euclidean space

Vectors, dot products, projection

The idea: a vector is a list of numbers and an arrow. The dot product is the one operation that converts geometry (angle, length, shadow) into arithmetic (multiply, add).

A vector in Rn is just an ordered list: a row of a CSV, the embedding of a sentence, the RGB of a pixel, the state of a system. Addition and scalar multiplication work coordinate-wise, and that is the whole definition of "linear" — you may stretch and you may add, nothing else.

Everything geometric comes from one product. For u, v ∈ Rn:

Definition · dot product

u · v = u1v1 + u2v2 + ⋯ + unvn = uTv
‖u‖ = √(u · u)    u · v = ‖u‖‖v‖ cos θ

Three consequences you will use constantly: u · v = 0 means perpendicular; u · v > 0 means the angle is acute (same general direction); and dividing by the lengths gives cosine similarity, a number in [−1, 1] that ignores magnitude and keeps only direction.

The projection of v onto u is the shadow v casts on the line through u:

proju(v) = u · vu · u u     and     v = proju(v) + (v − proju(v))

That split — one part along u, one part perpendicular to it — is the seed of Gram–Schmidt, of least squares, and of PCA. Learn it once here and you get three later chapters cheaply.

Bench 01 · dot productdrag either arrowhead
uvproju(v)

Drag v to be perpendicular to u and the dot product hits zero — that zero is what "independent features" means in a model.

Worked example · cosine similarity

u = (2, 0, 1), v = (3, 1, 0), w = (20, 0, 10)

u · v = 6 + 0 + 0 = 6. ‖u‖ = √5 ≈ 2.236, ‖v‖ = √10 ≈ 3.162.
cos θ = 6 / (2.236 × 3.162) = 0.849 → about 32°.
But u · w = 40 + 0 + 10 = 50, and cos θ = 50 / (2.236 × 22.36) = 1.000 → 0°.

w is ten times longer than u yet points in exactly the same direction. Raw dot products reward magnitude; cosine similarity throws magnitude away. That single choice is why search engines normalise vectors before comparing documents.

In your code

Every retrieval system you have touched is a dot product at scale. A vector database ranks documents by q·d / (‖q‖‖d‖); if the vectors are pre-normalised, that reduces to one matrix–vector product for the whole corpus, which is why the whole index can be a single dense matrix.

# the entire ranking step of a vector search
scores = D @ q          # (n_docs × dim) · (dim,) → (n_docs,)
top = np.argsort(-scores)[:10]
MA1522 · 02 · Linear systems

Gaussian elimination and what the answer looks like

The idea: a linear system has exactly three possible fates — no solution, one solution, or infinitely many. Row reduction is a mechanical procedure that always reveals which.

Write the system as an augmented matrix and apply only three moves, each of which is reversible and therefore preserves the solution set:

  1. swap two rows,
  2. multiply a row by a nonzero scalar,
  3. add a multiple of one row to another.

Push the matrix to row-echelon form (REF — zeros below each leading entry, a staircase), then to reduced row-echelon form (RREF — leading entries are 1 and are the only nonzero entry in their column). RREF is unique for a given matrix, which is why it can be trusted as a canonical answer.

Reading the RREF

  • A row like [0 0 0 | 1] — the system claims 0 = 1. Inconsistent, no solution.
  • Every variable has a pivot — exactly one solution.
  • Some column has no pivot — that variable is free. Infinitely many solutions, with one parameter per free variable.

Number of free variables = (number of unknowns) − (rank). This is the rank–nullity theorem in disguise, arriving five sections early.

Bench 02 · row reduction, one move at a timeedit the numbers, then step

Fractions are exact — the bench keeps rationals so you can compare with your own hand working.

Worked example · a system with a parameter

Solve x + y + z = 2, x + 2y + 3z = 5, 2x + 3y + 4z = 7.

1112 1235 2347  →  1112 0123 0123  →  10−1−1 0123 0000

Column 3 has no pivot, so z = t is free. Back-substituting: x = −1 + t, y = 3 − 2t. The solution set is a line in R3:

(x, y, z) = (−1, 3, 0) + t(1, −2, 1)

A particular solution plus a multiple of something in the null space. Every underdetermined system you ever solve has exactly this shape.

Where the machine differs from you Exact RREF is a hand tool. Numerically, dividing by a tiny pivot amplifies rounding error catastrophically, so real solvers use partial pivoting — swap in the largest available pivot before eliminating — and stop at REF rather than RREF, then back-substitute. That is what scipy.linalg.lu_factor does, and it is why np.linalg.solve(A,b) is both faster and more accurate than inv(A) @ b.
In your code

Elimination costs about 2n³/3 operations for an n×n system — cubic, so doubling the problem multiplies the work by eight. This single fact drives the whole design of numerical libraries: reuse a factorisation instead of re-solving, exploit sparsity, and never form an inverse you do not need.

MA1522 · 03 · Matrix algebra

Matrices, inverses, and LU

The idea: matrix multiplication is not "multiply the numbers". It is function composition, and that is why it is associative but not commutative.

Read Ax in the most useful way: as a combination of the columns of A.

1324 xy  =  x12 + y34

Once you see that, several later theorems become obvious rather than memorised: Ax = b is solvable exactly when b lies in the span of A's columns; the column space is the set of reachable outputs; and Ax = 0 asks which combinations of columns cancel out.

For products, (AB)x = A(Bx): apply B first, then A. Composition of functions is associative, so matrix multiplication is. Composition is not commutative — rotating then stretching differs from stretching then rotating — so AB ≠ BA in general.

Inverse · when it exists

A−1 exists iff A is square and its RREF is the identity, iff det A ≠ 0, iff the columns are linearly independent, iff Ax=0 only when x=0, iff rank = n. These are not five facts; they are one fact wearing five costumes. (The course calls this the invertibility theorem, and exams love it.)

For 2×2:   A−1 = 1ad − bc d−b−ca

Note the determinant in the denominator: as det → 0, the inverse blows up. Near-singular matrices are the numerical analyst's tar pit.

LU factorisation — elimination, saved for reuse

Gaussian elimination applied to A is itself a sequence of matrix multiplications by elementary matrices. Bundle them up and you get A = LU: L unit lower-triangular (the multipliers you used), U upper-triangular (the echelon form you reached). With pivoting it becomes PA = LU.

Why bother? Because solving Ax = b then splits into two triangular solves, each costing only n²:

LUx = b  ⟹  solve Ly = b forward, then Ux = y backward

Factor once at O(n³), then answer any number of right-hand sides at O(n²) each. In a pricing engine or a simulation loop where A is fixed and b changes every tick, this is the difference between shipping and not.

Worked example · LU by inspection

A = 2463. Eliminate row 2 using multiplier m = 6/2 = 3: row2 ← row2 − 3·row1 gives [0, −9].

A = 1031240−9 = LU

L holds the multipliers you would otherwise have thrown away; U is where elimination stopped. Also note det A = det L · det U = 1 × (2 × −9) = −18 — determinants come free with the factorisation.

In your code

Transposes and inverses reverse order, which trips people up in derivations: (AB)T = BTAT and (AB)−1 = B−1A−1. Socks then shoes; shoes off then socks off.

# factor once, reuse forever
lu, piv = scipy.linalg.lu_factor(A)
for b in stream:
    x = scipy.linalg.lu_solve((lu, piv), b)   # O(n²) each
MA1522 · 04 · Linear transformations & determinants

Matrices as maps; determinant as area

The idea: a linear map sends grid lines to grid lines, parallel and evenly spaced, with the origin nailed down. The determinant measures how much it inflates area — and whether it flips orientation.

A map T : Rn → Rm is linear if T(u+v) = T(u)+T(v) and T(cu) = cT(u). That is all. From it follows the most useful fact in the chapter:

The standard matrix

A linear map is completely determined by what it does to the standard basis vectors. Feed it e1, e2, …, en, and stack the outputs as columns:

A = [ T(e1)   T(e2)   ⋯   T(en) ]

Want the matrix of a 90° rotation? e1=(1,0) goes to (0,1), e2=(0,1) goes to (−1,0). So the matrix is 0−110. No formula memorisation required — just track the basis.

Return to Bench 00 at the top and try these while watching the readout:

  • Squash — the second column becomes a multiple of the first. The whole plane collapses onto a line, determinant 0, information destroyed, no inverse.
  • Reflect — determinant −1. Same area, opposite orientation. A left hand becomes a right hand.
  • Shear — determinant 1. Area preserved, angles wrecked. This is why "preserves area" and "preserves shape" are very different requirements.

Determinant · the properties that matter

  • det(AB) = det(A)·det(B) — composing maps multiplies the area factors.
  • det(AT) = det(A); det(A−1) = 1/det(A).
  • Swapping two rows flips the sign; adding a multiple of one row to another changes nothing.
  • For a triangular matrix, det is the product of the diagonal — which is exactly why we compute it from LU, in O(n³), rather than from cofactor expansion, which is O(n!).

Cofactor expansion for a 20×20 matrix would take longer than the age of the universe. LU takes microseconds. Same number, different algorithm.

In your code

Graphics pipelines are stacks of these maps: model → world → camera → clip, each a matrix, multiplied together once and applied to millions of vertices. Translation is not linear (it moves the origin), which is precisely why graphics uses 4×4 homogeneous coordinates — bolting on an extra dimension turns a translation into a shear, and shears are linear.

MA1522 · 05 · Vector spaces

Span, independence, basis, rank

The idea: given a pile of vectors, only two questions matter — what can you reach with them (span), and how many of them are redundant (independence). Rank answers both at once.

Span is the set of all linear combinations: everywhere you can get to by scaling and adding. Two vectors in R³ that point in different directions span a plane; add a third that lies in that plane and you have gained nothing.

Linear independence is the formal version of "nothing is redundant": the only way to write c1v1 + ⋯ + ckvk = 0 is with all ci = 0. If some non-trivial combination cancels, one vector is expressible via the others and can be deleted without shrinking the span.

Basis and dimension

A basis of a subspace is a spanning set that is also independent — the smallest possible set of directions that still reaches everything, with no repeats. Every basis of a given subspace has the same size; that number is the dimension.

A basis is a coordinate system. Choosing a good one is often the entire content of a hard problem: PCA chooses a basis where the data's variance is axis-aligned; Fourier chooses a basis where convolution becomes multiplication.

The four subspaces, and one theorem

For an m×n matrix A:

  • Column space ⊆ Rm — all reachable outputs Ax. Its dimension is the rank.
  • Null space ⊆ Rn — all inputs killed to zero, Ax=0. Its dimension is the nullity.
  • Row space — span of the rows; its dimension is also the rank (row rank = column rank, a genuinely surprising theorem).
  • Left null space — ATy = 0, the directions no output ever touches.

Rank–nullity

rank(A) + nullity(A) = n   (number of columns)

Dimensions in = dimensions preserved + dimensions destroyed. Nothing goes missing. In practice: rank = number of pivots in the RREF, and nullity = number of free variables. You already computed both in Bench 02 without knowing their names.

Bench 03 · span & rankdrag the arrowheads; watch the span collapse

Two vectors in the plane span everything unless they line up — then the span drops to a single line, rank falls to 1, and the null space appears out of nowhere with dimension 1.

Worked example · rank of a data matrix

A table with columns height in cm, height in inches, weight has three columns but rank 2 — the second column is 0.3937 × the first. Regression on it fails: ATA is singular and there is no unique fit, because infinitely many coefficient pairs give the same prediction.

This is multicollinearity, and it is not a statistical curiosity — it is rank deficiency, visible in the RREF. Fixes (drop a column, ridge regularisation, use the pseudoinverse) all amount to restoring a unique choice.

In your code

Rank is not computed by row reduction in practice. Floating point turns exact zeros into 1e−17, so libraries compute the singular values and count how many exceed a tolerance — np.linalg.matrix_rank is an SVD in disguise. The honest question is never "is it singular?" but "how close to singular is it?", answered by the condition number.

MA1522 · 06 · Eigenvalues & diagonalisation

The directions a matrix does not turn

The idea: most vectors get rotated by a matrix. A few special ones only get stretched. Find those and repeated application becomes trivial arithmetic.

Definition

Av = λv,   v ≠ 0

Rearranged: (A − λI)v = 0 has a non-zero solution, so A − λI must be singular, so

det(A − λI) = 0   — the characteristic equation

Solve it for λ (the eigenvalues), then find the null space of A − λI for each (the eigenvectors, the eigenspace).

Diagonalisation. If A has n independent eigenvectors, stack them as columns of P and put the eigenvalues on the diagonal of D. Then A = PDP−1. Read that right to left as a sentence: change into eigen-coordinates, stretch each axis, change back.

The payoff is powers. Everything in the middle cancels:

Ak = PDkP−1,    Dk = diag(λ1k, …, λnk)

Raising a matrix to the 1000th power costs one factorisation and n scalar powers. And it tells you the long-run behaviour at a glance: if all |λ| < 1 the system decays to zero; if some |λ| > 1 it explodes; if the largest is exactly 1 it settles into a steady state.

Bench 04 · iterate v ← Avdrag the start vector, then step

Each step normalises the drawing so the path stays on screen; the readout shows the true growth factor. That normalise-and-repeat loop is the power method.

Worked example · a Markov chain by hand

Users move between two plans each month: 90% of Basic stay, 10% upgrade; 20% of Premium downgrade, 80% stay.

A = 0.90.20.10.8

Characteristic equation: (0.9−λ)(0.8−λ) − 0.02 = λ² − 1.7λ + 0.7 = 0, so λ = 1 and λ = 0.7.

The λ=1 eigenvector solves (A−I)v=0: −0.1v₁ + 0.2v₂ = 0, so v = (2,1). Normalised to sum to 1: (2/3, 1/3). Whatever the starting split, the population converges to two-thirds Basic — and the 0.7 tells you how fast the memory of the initial state dies out (30% of the gap closes per month).

Not everything diagonalises 1101 has λ = 1 twice but only one independent eigenvector — algebraic multiplicity 2, geometric multiplicity 1. It is defective. Rotations have no real eigenvectors at all (nothing keeps its direction), only complex ones. Both are ordinary cases, not pathologies; they are the reason the SVD, which always exists, is the more dependable tool.
In your code

PageRank is the dominant eigenvector of the web's link matrix, found by exactly the loop in Bench 04. Graph clustering reads eigenvectors of the Laplacian. In deep learning, whether gradients vanish or explode across layers is a statement about the eigenvalues of the repeated Jacobian — |λ|<1 everywhere means the signal dies before it reaches layer one.

MA1522 · 07 · Orthogonality

Right angles, QR, and least squares

The idea: in an orthonormal basis, coordinates are just dot products — no solving required. And when a system has no solution, the best available answer is a projection.

A set is orthonormal if the vectors are mutually perpendicular and each has length 1. Then for any v in their span, v = (v·q1)q1 + ⋯ + (v·qk)qk. Finding coordinates degrades from a linear solve to k dot products.

A square matrix Q with orthonormal columns is orthogonal: QTQ = I, so Q−1 = QT — inversion for free. Such maps preserve every length and every angle; they are exactly the rotations and reflections. Numerically they are gold, because they never amplify error.

Gram–Schmidt → QR

Take independent a1, a2, …. Keep the first. For each next one, subtract its projection onto everything already kept, then normalise:

uk = ak − Σj<k projqj(ak),   qk = uk/‖uk‖

Collecting the bookkeeping gives A = QR, with Q orthonormal and R upper-triangular. It is the orthogonal cousin of LU, and it is the workhorse behind stable least squares and eigenvalue algorithms.

Least squares — solving the unsolvable

With more equations than unknowns, Ax=b usually has no solution: b sits outside the column space. The next best thing is the x̂ that makes Ax̂ the closest point in the column space to b — the projection. The error must then be perpendicular to that space:

AT(b − Ax̂) = 0  ⟹  ATA x̂ = ATb  — the normal equations

That one line is linear regression. Fit a line, a polynomial, or a 200-feature model — same equation, different A.

Bench 05 · least squarestap to add points, drag to move them

The vertical hairs are residuals. The fit minimises the sum of their squares, which is why one distant point drags the line so hard.

Worked example · fitting a line through three points

Points (1,1), (2,2), (3,2), model y = c + mx.

A = 111213, b = 122, ATA = 36614, ATb = 511

Solve 3c + 6m = 5, 6c + 14m = 11: subtract twice the first from the second → 2m = 1, so m = 0.5, c = 2/3. Fit: y = 0.667 + 0.5x. No line passes through all three points, but this one minimises the squared vertical error.

Don't form ATA Squaring a matrix squares its condition number, so the normal equations lose roughly twice the digits. Production code solves least squares via QR (numpy.linalg.lstsq) or SVD. The normal equations are how you derive and understand the answer, not how you compute it.
MA1522 · 08 · Singular value decomposition

SVD and PCA — the summit of the course

The idea: every matrix, of any shape, is a rotation, then a stretch along perpendicular axes, then another rotation. No exceptions, no defective cases.

The decomposition

A = U Σ VT

V's columns (orthonormal) are the input directions; Σ is diagonal with the singular values σ1 ≥ σ2 ≥ ⋯ ≥ 0; U's columns (orthonormal) are the output directions. Concretely: Avi = σiui.

Where it comes from: ATA is symmetric and positive semi-definite, so it diagonalises with non-negative eigenvalues. Its eigenvectors are the vi, and σi = √λi. That is the whole construction — eigen-theory applied to ATA.

Now the part that earns the chapter its reputation. Write the SVD as a sum of rank-1 pieces, ordered by importance:

A = σ1u1v1T + σ2u2v2T + ⋯ + σrurvrT

Truncate after k terms and you get Ak. The Eckart–Young theorem says this is the best possible rank-k approximation of A, in the least-squares sense. Not a good heuristic — provably optimal. That single fact underwrites image compression, latent semantic analysis, recommender systems, and noise reduction.

Bench 06 · rank-k approximationhow few numbers can still spell a word?

Left: the original 32×96 image. Right: the sum of the first k rank-1 layers. Storage falls from 32×96 numbers to k×(32+96+1).

PCA is SVD wearing a lab coat

Centre your data (subtract the column means), then the covariance matrix is C = 1n−1XTX. Its eigenvectors are the principal components — the perpendicular directions of greatest variance — and its eigenvalues say how much variance each captures. But those eigenvectors are exactly the right singular vectors of X, so PCA is done by taking the SVD of the centred data and never forming C at all.

Bench 07 · principal componentstilt and squeeze the cloud

When the correlation is near zero the two components carry similar variance and there is nothing to compress. Correlation is redundancy, and redundancy is what PCA harvests.

In your code

The condition number κ = σmax/σmin is the number to check before trusting any linear solve: it bounds how much a relative error in your data is amplified in the answer. κ ≈ 108 in double precision means roughly half your significant digits are already gone.

The pseudoinverse A+ = VΣ+UT (invert the non-zero σ's, transpose) solves least squares even when ATA is singular — it quietly returns the minimum-norm solution instead of failing.

U, s, Vt = np.linalg.svd(X_centered, full_matrices=False)
explained = s**2 / (s**2).sum()      # variance per component
Z = X_centered @ Vt[:k].T            # project to k dims

MA1521 · 09 · Limits & continuity

Limits, and why big-O is one

The idea: a limit describes where a function is heading, regardless of whether it ever arrives. Complexity analysis is the same statement about algorithms.

limx→a f(x) = L means: you can force f(x) as close to L as you like by taking x close enough to a — without ever setting x = a. That exclusion is the whole point. (x²−1)/(x−1) is undefined at 1, yet its limit there is a perfectly definite 2.

The toolkit, in the order you should reach for it

  1. Substitute. If the function is continuous at a, the limit is f(a). Done.
  2. Factor or rationalise to cancel the offending term: (x²−1)/(x−1) = x+1 → 2.
  3. Squeeze theorem. If g ≤ f ≤ h and both ends go to L, f has no choice. This is how limx→0 x sin(1/x) = 0 is proved.
  4. L'Hôpital for 0/0 or ∞/∞ only: differentiate top and bottom separately and try again.

Continuity at a means all three exist and agree: f(a), the limit, and each other. Continuous functions on a closed interval attain a maximum and a minimum — the guarantee that makes optimisation problems well-posed.

The two limits worth memorising, because everything else is built from them:

limx→0 sin xx = 1      limn→∞ (1 + 1n)n = e
Bench 08 · limits of ratios = big-Owhich function wins as n grows?

The curve is f(n)/g(n). If it settles to zero, f is dominated by g. If it settles to a positive constant, they are the same order. If it runs away, f wins.

In your code

f = O(g) is precisely lim sup f/g < ∞; f = o(g) is lim f/g = 0; f = Θ(g) is a finite positive limit. When you argue that constants "don't matter asymptotically", you are taking a limit — and the bench shows exactly why 100n still loses to n², but only after n = 100. For small inputs the constant is the whole story, which is why real sort implementations switch to insertion sort below a threshold.

MA1521 · 10 · Derivatives

The derivative, and the chain rule that runs your models

The idea: zoom far enough into any smooth curve and it looks like a straight line. The derivative is that line's slope — the best linear approximation at a point.

Definition

f′(x) = limh→0 f(x+h) − f(x)h

The fraction is the slope of a secant through two nearby points; the limit is the tangent. Read as a rate: how fast the output moves per unit of input. Read as an approximation: f(x+h) ≈ f(x) + f′(x)h — the linearisation that every gradient step relies on.

Bench 09 · secant → tangentshrink h and watch the slope settle

The rules, compressed

Power(xⁿ)′ = n xn−1
Product(uv)′ = u′v + uv′
Quotient(u/v)′ = (u′v − uv′)/v²
Chain(f∘g)′(x) = f′(g(x)) · g′(x)
Exp / log(eˣ)′ = eˣ,  (ln x)′ = 1/x
Trig(sin)′ = cos,  (cos)′ = −sin,  (tan)′ = sec²
Inverse(f−1)′(y) = 1 / f′(x)

Implicit differentiation: differentiate both sides with respect to x, treating y as a function of x, and solve for dy/dx. For x² + y² = 25: 2x + 2y·y′ = 0, so y′ = −x/y.

The chain rule is backpropagation

Composition is how neural networks are built, so the chain rule is how they are trained. Take one neuron with a squared loss: z = wx + b, a = σ(z), L = (a − y)². Then

∂L∂w = ∂L∂a · ∂a∂z · ∂z∂w = 2(a−y) · σ′(z) · x

Backprop is nothing more than evaluating that product right-to-left, caching each factor so it is computed once. The bench below runs a real forward and backward pass on the numbers you choose.

MA1521 · 11 · Applications of the derivative

Shape of a curve, and Newton's method

The idea: the first derivative tells you which way the curve leans, the second tells you which way it bends, and together they locate every maximum and minimum.

Finding extrema

  1. Critical points: where f′(x) = 0 or f′ fails to exist.
  2. First derivative test: f′ changing + to − gives a local max; − to + gives a local min.
  3. Second derivative test: f″(c) > 0 → concave up → minimum. f″(c) < 0 → maximum. f″(c) = 0 → inconclusive, fall back to the first test.
  4. Inflection points: where f″ changes sign — the bend reverses.
  5. On a closed interval, also check the endpoints. The global max may not be critical at all.

Two theorems underwrite all of it. The Mean Value Theorem: for f continuous on [a,b] and differentiable inside, some c has f′(c) = (f(b)−f(a))/(b−a) — at some instant your speed equalled your average speed. Nearly every error bound in numerical analysis, including the ones below, is an MVT argument.

Newton's method — the derivative as a solver

To solve f(x) = 0: stand at xn, replace the curve with its tangent line, and jump to where that line crosses zero.

xn+1 = xn − f(xn)f′(xn)

Convergence is quadratic near a simple root — the number of correct digits roughly doubles each step, which is why it typically needs five iterations, not five hundred. It also fails spectacularly if you start near a point where f′ ≈ 0: the tangent is nearly flat and flings you across the number line.

Bench 11 · Newton's methoddrag the starting point, then step

Try starting near a turning point of the cubic and watch the tangent throw you far away — the method is fast, not safe.

MA1521 · 12 · Integration

Integrals, and the theorem that ties the course together

The idea: an integral is a limit of sums. The fundamental theorem says that this limit can be computed by undoing a derivative — which is why calculus is practical rather than merely true.

Chop [a,b] into n slices, approximate each by a rectangle, add them up, then let n → ∞:

∫ab f(x) dx = limn→∞ Σi=1n f(xi*) Δx

Fundamental theorem of calculus

Part 1 — differentiation undoes integration: d/dx ∫ax f(t)dt = f(x).

Part 2 — evaluation: if F′ = f, then ∫ab f = F(b) − F(a).

An infinite summation problem becomes two function evaluations. This is the single largest labour saving in mathematics.

Bench 12 · Riemann sumswatch the error, not the picture

Left and right sums lose accuracy like O(1/n); midpoint and trapezium like O(1/n²). Doubling the slices buys you four times the accuracy — that is the whole argument for better quadrature rules.

Techniques, and when to use which

  • Substitution — undoes the chain rule. Spot an inner function whose derivative is loitering nearby: ∫ 2x·ex²dx, set u = x².
  • By parts — undoes the product rule: ∫u dv = uv − ∫v du. Use it when one factor gets simpler on differentiating (a polynomial) and the other is harmless on integrating (eˣ, sin, cos). For ∫x ln x dx take u = ln x.
  • Partial fractions — split a rational function into pieces you already know: 1/((x−1)(x+1)) = ½[1/(x−1) − 1/(x+1)].
  • Trigonometric substitution — for √(a²−x²) try x = a sin θ.
  • Improper integrals — infinite limit or infinite integrand: define as a limit and check convergence. ∫1∞x−pdx converges iff p > 1.
In your code

Continuous probability is integration: a density integrates to 1, expectation is ∫x f(x)dx, and a CDF is the running integral of the PDF. Every time you sample from a distribution by inverse-transform, you are inverting an integral. And the reason Monte Carlo dominates in high dimensions is that grid-based quadrature costs O(nd) while sampling error falls like 1/√N regardless of d.

MA1521 · 13 · Sequences & series

Infinite sums, and Taylor's approximation machine

The idea: adding infinitely many things can give a finite answer, provided the terms shrink fast enough. Taylor series then let you rebuild almost any function out of polynomials.

Convergence tests, in the order to try them

  1. n-th term test: if an ↛ 0, the series diverges. (The converse is false — the harmonic series has terms going to zero and still diverges.)
  2. Geometric: Σarn converges iff |r| < 1, to a/(1−r).
  3. p-series: Σ1/np converges iff p > 1.
  4. Ratio test: L = lim|an+1/an|. L < 1 converges, L > 1 diverges, L = 1 tells you nothing.
  5. Comparison / integral test: bound against something you already know, or against ∫f.
  6. Alternating series: signs alternate and |an| decreases to 0 → converges, with error smaller than the first omitted term.

Two of these are load-bearing in computer science. The geometric series is why a dynamic array that doubles in size has amortised O(1) append: total copying is 1 + 2 + 4 + ⋯ + n < 2n. And Σ1/k ≈ ln n + γ — the harmonic number — is the expected cost of quicksort, of coupon-collecting, and of hash probing.

Taylor and Maclaurin series

f(x) = Σn=0∞ f(n)(a)n!(x − a)n

Match the value, then the slope, then the curvature, then the rate of change of curvature, and so on. The four to know by heart:

The radius of convergence is found with the ratio test. Outside it the series is worthless, no matter how well-behaved the function looks.

For the last two, the approximation refuses to follow the curve past |x| = 1 however many terms you add. That wall is the radius of convergence, and no amount of compute gets you past it.

In your code

Your standard library computes sin, exp and log from truncated series (plus argument reduction and a polynomial fitted to minimise worst-case error). Taylor expansion is also how you rescue a formula from catastrophic cancellation: for tiny x, exp(x)-1 loses all precision, so expm1(x) uses x + x²/2 + ⋯ instead — same value, many more correct digits.

MA1521 · 14 · Functions of several variables

Partial derivatives and the gradient

The idea: with many inputs, "the slope" splinters into one slope per direction. Collect them into a vector and you get the gradient — which points straight uphill.

A partial derivative ∂f/∂x is the ordinary derivative taken with every other variable frozen. For f(x,y) = x²y + 3y³: fx = 2xy and fy = x² + 9y². Mixed partials commute for well-behaved functions (fxy = fyx, Clairaut), which is why the Hessian is symmetric.

Gradient and directional derivative

∇f = (fx, fy)     Duf = ∇f · u  (u a unit vector)

Three consequences, straight from ∇f·u = ‖∇f‖cos θ:

  • The steepest ascent is along ∇f itself, and the steepest rate is ‖∇f‖.
  • Perpendicular to the gradient, the function does not change at all — so ∇f is always perpendicular to the contour line.
  • Steepest descent is −∇f. That is the entire idea of gradient descent, and it is just the dot product from Section 1 again.

Multivariable chain rule: if x=x(t), y=y(t) then df/dt = fx·x′(t) + fy·y′(t). Sum over every path the influence can travel — which is exactly how autodiff handles a node with several children.

MA1521 · 15 · Extrema & optimisation

Finding the bottom of the bowl

The idea: at a maximum or minimum the gradient vanishes. The second derivatives then decide whether you are at a peak, a pit, or a mountain pass.

Second derivative test in two variables

At a critical point where fx = fy = 0, let D = fxxfyy − fxy² (the determinant of the Hessian).

  • D > 0 and fxx > 0 → local minimum.
  • D > 0 and fxx < 0 → local maximum.
  • D < 0 → saddle point: up one way, down another.
  • D = 0 → inconclusive.

In the language of Part One: the Hessian is a symmetric matrix, and this test just asks about the signs of its eigenvalues. All positive → bowl. All negative → dome. Mixed signs → saddle. The two courses are describing the same object.

Lagrange multipliers. To optimise f subject to a constraint g = c, note that at the best point the contours of f must be tangent to the constraint curve — otherwise you could slide along the constraint and do better. Tangency means parallel gradients:

∇f = λ∇g,    g(x,y) = c

Solve the system. The multiplier λ is not waste: it is the shadow price, the rate at which the optimum improves as you relax the constraint by one unit.

Gradient descent, and why the step size fights the curvature

Repeat x ← x − η∇f(x). On a quadratic bowl f = ½(ax² + by²), the update is diagonal, and along each axis the error is multiplied by (1 − ηλ) per step. So:

  • It converges only if η < 2/λmax — the sharpest direction sets the speed limit.
  • The slowest direction converges at rate 1 − ηλmin.
  • So the whole difficulty is the ratio λmax/λmin — the condition number from the SVD section. An ill-conditioned loss surface makes descent zig-zag down a narrow valley.

Feature scaling, batch normalisation, momentum and Adam are all attempts to fix the same eigenvalue problem.

MA1521 · 16 · Differential equations

ODEs and the simplest numerical solver

The idea: an ODE describes a rule for change and asks you to recover the thing changing. When you cannot solve it on paper, you step forward along the tangent instead.

The two you must be able to solve by hand

Separable — get all the y's on one side: dy/dx = g(x)h(y) → ∫dy/h(y) = ∫g(x)dx.
Example: dy/dx = ky → ln|y| = kx + C → y = Aekx. Exponential growth and decay, half-lives, compound interest.

First-order linear — y′ + P(x)y = Q(x). Multiply by the integrating factor μ = e∫P dx, which makes the left side an exact derivative (μy)′, then integrate both sides.

Logistic — y′ = ry(1 − y/K) is separable via partial fractions and gives the S-curve that every adoption model reaches for.

Euler's method turns the definition of the derivative into an algorithm. From y′ = f(x,y) and y(x₀) = y₀:

yn+1 = yn + h·f(xn, yn)

Follow the tangent for a short distance h, recompute the slope, repeat. Global error is O(h) — halve the step, halve the error, which is poor. Runge–Kutta 4 samples the slope four times per step for O(h⁴), and is what scipy.integrate.solve_ivp uses by default.

On the decay equation, push h past 2/1.5 = 1.33 and the numerical solution oscillates and blows up while the true one decays quietly. Stability is not accuracy.

Both pens · one page

Where the two courses meet

The idea: linear algebra gives you the object; calculus tells you which object is best. Almost every model you will ship is that sentence, made concrete.

Here is linear regression derived twice. First, the calculus way. The loss is a function of the parameter vector x:

L(x) = ‖Ax − b‖² = (Ax − b)T(Ax − b)

Expand, differentiate with respect to the vector x, and set the gradient to zero:

∇L = 2AT(Ax − b) = 0  ⟹  ATA x = ATb

Now the linear algebra way: the residual must be perpendicular to the column space, so AT(b − Ax) = 0. Same equation. One route reasons about slopes; the other reasons about right angles. They agree because minimising a squared distance is finding a perpendicular — the second derivative test even confirms it, since the Hessian 2ATA is positive semi-definite, so the critical point is a genuine minimum.

If you only keep six things

  1. Ax is a combination of A's columns. Solvability, rank, span and least squares all fall out of this one reading.
  2. Determinant is an area factor. Zero means collapse, which means no inverse, which means no unique solution.
  3. Eigenvectors are the directions a matrix leaves alone. Repeated application is then just scalar powers.
  4. Every matrix is rotate–stretch–rotate. The SVD always exists, and truncating it is provably the best low-rank summary.
  5. A derivative is a local linear approximation. Newton, gradient descent, Euler and Taylor are all that one sentence, iterated.
  6. The gradient is perpendicular to the contour. Steepest descent, Lagrange multipliers and the normal equations are the same geometry three times.
